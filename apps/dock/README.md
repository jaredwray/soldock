# `dock` — the Worker

> Status: **started**. Domain modules live in [`src/`](src/), workerd integration tests in
> [`test/`](test/), and D1 migrations in [`migrations/`](migrations/). Mail, Drive (with Docs and
> Sheets), Chat, identity (with OAuth for agents), REST and MCP have their first layer.

The entire backend as one deployable Worker (modular monolith): `fetch`, `email`, `queue` and `scheduled` handlers, every Durable Object and Workflow class, serving the SPA, REST, MCP, OAuth, WebSockets and file transfer from one origin.

## Layout

| Path | What |
| --- | --- |
| [`wrangler.jsonc`](wrangler.jsonc) | Worker config: pinned compatibility date, `nodejs_compat` and `enable_request_signal`, observability, static assets with SPA fallback, and `run_worker_first` for every Worker-owned prefix. The top level is production. `env.development` is the `soldock-dock-dev` Worker at its custom domain `work.soldock.org` ([docs/self-hosting.md](../../docs/self-hosting.md)). Neither Worker serves `workers.dev` or Preview URLs: one origin each |
| [`src/index.ts`](src/index.ts) | Composition root. Sends Worker-owned paths to the Hono app and everything else to static assets. Exports the `email`, `queue` and `scheduled` handlers, and the Durable Object classes `MailboxDO`, `DriveSpaceDO`, `DocumentDO` and `ChatRoomDO` |
| [`src/handlers.ts`](src/handlers.ts) | The operation handlers of each domain, joined into one map for the REST and MCP adapters, and the change feed of each resource kind for MCP subscriptions |
| [`src/routes.ts`](src/routes.ts) | `WORKER_PREFIXES`, the paths the Worker owns. Must match `run_worker_first`; `test/config.test.ts` enforces it |
| [`src/app.ts`](src/app.ts) | The Hono app: request ids, problem+json errors, `/auth/*`, `/oauth/*` and `/.well-known/*`, the REST routes and `/mcp` |
| [`src/platform/`](src/platform/) | Cross-cutting runtime services: HTTP plumbing, ids, crypto, logs, the operation invoker |
| [`src/identity/`](src/identity/) | Directory, API keys, sessions, first-run setup, the OAuth server for agents, account, directory and OAuth operations |
| [`src/api/`](src/api/), [`src/mcp/`](src/mcp/) | The REST and MCP adapters, generated from `@soldock/contracts` |
| [`src/mail/`](src/mail/) | Mail: inbound pipeline, `MailboxDO`, search, sanitizer, MIME, outbound |
| [`src/drive/`](src/drive/) | Drive: `DriveSpaceDO` (items, versions, grants, trash, search, stars), uploads and downloads through R2 |
| [`src/collab/`](src/collab/) | `DocumentDO`: the content of one doc or one sheet, with a revision counter |
| [`src/docs/`](src/docs/), [`src/sheets/`](src/sheets/) | Docs (the block tree, Markdown) and Sheets (cells, the formula engine) |
| [`src/chat/`](src/chat/) | Chat: `ChatRoomDO` (one room or direct message: members, messages, read markers), and the room index in D1 |
| [`migrations/`](migrations/) | D1 migrations of the `DIRECTORY` database |
| [`worker-configuration.d.ts`](worker-configuration.d.ts) | Generated by `wrangler types`. Never edit it by hand |
| [`budgets.json`](budgets.json) | Bundle-size and startup-time budgets, checked by [`tools/budgets`](../../tools/budgets/) |

## Request handling today

- Paths under a Worker-owned prefix (`/api/`, `/mcp`, `/oauth/`, `/.well-known/`, `/auth/`, `/ws/`,
  `/blob/`, `/dl/`, `/hooks/`) go to the Hono app. Unknown ones get a `404` with an
  `application/problem+json` body, never the SPA.
- Every app response carries a server-generated `x-request-id`. A client-supplied one is ignored.
- `GET /healthz` returns `{ "ok": true }` without authentication, D1, or static assets. It checks Worker liveness only.
- `GET /api/v1/system/ping` returns `{ "ok": true }`.
- `/api/v1/*`: one route for each operation in `@soldock/contracts` ([`src/api/`](src/api/)).
- `/mcp`: the MCP endpoint, with one tool for each operation and the inbox of each mailbox as a
  resource ([`src/mcp/`](src/mcp/)). It speaks protocol 2026-07-28 and the older protocols. A
  `subscriptions/listen` request gets a long-lived SSE response with a notification for new mail.
  Its `401` names the OAuth metadata.
- `/.well-known/oauth-protected-resource[/mcp]`, `/.well-known/oauth-authorization-server`,
  `/oauth/register`, `/oauth/authorize` and `/oauth/token`: the OAuth server for MCP clients. A
  person approves a client on the `/connect/<id>` page of the SPA
  ([`src/identity/`](src/identity/README.md#oauth-for-agents)).
- `/auth/setup` (`GET` status, `POST` setup), `/auth/setup/verify`, `/auth/session`, `/auth/sign-out`:
  first-run setup and browser sign-in with the address, the password and an optional TOTP code
  ([`src/identity/`](src/identity/)).
- Any other path is served by static assets (the `apps/web` build), which fall back to `index.html`
  for SPA routes. In production, browser navigations go to the assets, and the Worker does not run.
- `email` accepts mail for known addresses and rejects other mail at SMTP time. `queue` consumes
  `soldock-mail-inbound` and acknowledges batches of other queues. `scheduled` logs.

## Bindings

| Binding | Type | Use |
| --- | --- | --- |
| `ASSETS` | Static assets | The SPA (`../web/dist`) |
| `DIRECTORY` | D1 `soldock-directory` | Principals (with password hashes and TOTP secrets), addresses, API keys, sessions, OAuth clients, requests and grants, mail domains, and the room index of Chat |
| `BLOBS` | R2 `soldock-blobs` | Raw MIME of each message, and the bytes of each version of each Drive file |
| `MAIL_INBOUND`, `MAIL_INBOUND_DLQ` | Queue producers | Inbound jobs and their dead letters. The Worker consumes `soldock-mail-inbound` |
| `EMAIL` | `send_email` | Outbound mail through Email Service |
| `MAILBOX` | Durable Object `MailboxDO` (SQLite) | One mailbox for each principal and each team mailbox. It also accepts the hibernatable watch sockets of MCP subscriptions |
| `DRIVE_SPACE` | Durable Object `DriveSpaceDO` (SQLite) | One drive for each principal |
| `DOCUMENT` | Durable Object `DocumentDO` (SQLite) | The content of each doc and each sheet |
| `CHAT_ROOM` | Durable Object `ChatRoomDO` (SQLite) | One room or one direct message of Chat |
| `MAIL_AUTHSERV_ID` | Var | The receiving server whose Authentication-Results header counts |
| `SETUP_TOKEN` | Secret (optional) | Turns on `POST /auth/setup` while it has at least 32 characters. `GET /auth/setup` reports its state, never its value. Delete it after setup |

`wrangler.jsonc` has no resource ids. `wrangler deploy` provisions the D1 database, the R2 bucket
and the queues by name on the first deploy, and finds them by name after that.

## Commands

Run these from the repository root.

```sh
pnpm build                                  # builds apps/web into apps/web/dist (assets for dev, tests and deploy)
pnpm test                                   # includes the workerd project ("dock")
pnpm --filter @soldock/dock migrate:local   # applies the D1 migrations to the local database of wrangler dev
pnpm --filter @soldock/dock dev             # wrangler dev
pnpm --filter @soldock/dock types           # regenerate worker-configuration.d.ts after editing wrangler.jsonc
pnpm types:check                            # fails if worker-configuration.d.ts is stale (CI)
pnpm budgets:check                          # builds with --dry-run, profiles startup, compares to budgets.json (CI)
pnpm run deploy:check                       # wrangler deploy --dry-run --env development (CI)
scripts/smoke-check.sh http://localhost:8787  # the post-deploy smoke check, against wrangler dev
```

`deploy-development.yaml` runs `pnpm run deploy:development` and the remote D1 migrations in GitHub
Actions on each push to `main`, then smoke checks `https://work.soldock.org`. Never run them from a
developer machine or an agent session.
[`docs/development.md`](../../docs/development.md) shows how to run the whole product locally,
with injected inbound mail.

## Data inventory

| State | Module | Where |
| --- | --- | --- |
| Directory (principals with their password hashes and TOTP secrets, addresses, API keys, sessions, reset lock, mail domains, team mailboxes and their members, OAuth clients, requests and grants) | [`identity`](src/identity/README.md) | D1 `DIRECTORY` |
| Mailboxes (messages, threads, labels, search index, delivery, outbox, idempotency keys) | [`mail`](src/mail/README.md) | `MailboxDO` SQLite |
| Raw MIME | [`mail`](src/mail/README.md) | R2 `BLOBS`, `mail/raw/<mailbox id>/<sha256>` |
| Inbound jobs | [`mail`](src/mail/README.md) | Queues `soldock-mail-inbound` and `soldock-mail-inbound-dlq` |
| Drives (items, versions, grants, search index, stars, shared-with-me index, outbox, idempotency keys) | [`drive`](src/drive/README.md) | `DriveSpaceDO` SQLite |
| File bytes | [`drive`](src/drive/README.md) | R2 `BLOBS`, `drive/<space id>/<item id>/<version id>` |
| The content of each doc and each sheet, with its revision | [`collab`](src/collab/README.md) | `DocumentDO` SQLite |
| Rooms and direct messages (members, read markers, messages, outbox, idempotency keys) | [`chat`](src/chat/README.md) | `ChatRoomDO` SQLite |
| The room index of Chat (a copy for the lists) | [`chat`](src/chat/README.md) | D1 `DIRECTORY`, tables `chat_rooms` and `chat_members` |

`MailboxDO`, `DriveSpaceDO` and `ChatRoomDO` do not extend a `SoldockObject` base class yet. Each has its own
migrations, outbox and idempotency table. When `SoldockObject` exists, they move onto it. Backups:
not built yet.
